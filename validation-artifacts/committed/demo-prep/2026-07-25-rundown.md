**Basis:** deployed `main` (worktree HEAD `2aacf30` == `origin/main`). Every capability claim below is something the live product does; every limit is real. Jurisdiction/MUTCD facts come from repo data — anything I could not verify from code is marked `[VERIFY]`.
**How to read this:** raw material, not the final briefing. Ryan + chat-Claude shape it into the talk track. Accuracy over polish.

> **One-line framing for James:** *The tool takes a dropped pin and a scenario, reads the road from OpenStreetMap, and generates a full CDOT-compliant traffic-control package — plan sheet, device list, crew instructions, priced quote — where every dimension carries a MUTCD/CDOT citation. Its most distinctive trait is that it refuses to draw plans for situations it can't stand behind, and tells you why.*

## 1. What the tool does today — capability inventory

### 1.1 Two scenario types generate real plans (five more are built but gated)

The product defines **seven** scenario kinds in code but **enables exactly two** end-to-end today. The gate is a single mirrored pair of constants that must match — backend `ENABLED_SCENARIOS = {"shoulder", "flagger_lane_closure"}` (`src/api/render_api.py:92`) and frontend `ENABLED_SCENARIO_KINDS` (`conestruct/site/lib/scenarios/index.ts:273`). The scenario picker only renders enabled kinds, so James only ever sees the two live ones.

- **Shoulder work** *(live)* — closes the shoulder while traffic stays in its lane. Maps to CDOT S-630-1 Cases 11/11b/26/27 (TA-3, or TA-5 on freeway). Inputs (`ShoulderForm.tsx`): road type, speed 25–75, lanes/direction, lane width, work type, work-zone length, night op, optional work-zone speed reduction. **Credible detail:** uses the shoulder taper specifically (`L/3`, `validators.py:1494`), and surfaces the MUTCD taper law inline — *"≥45 mph uses L=W·S."*
- **Flagger lane closure** *(live)* — a TA-10 one-lane, two-way flagging operation alternating traffic through the single open lane. Maps to MUTCD TA-10 + S-630-1 Case 17/42. Inputs (`FlaggerForm.tsx`): road type (rural 2-lane or urban arterial), speed 25–55, lane width, work type, length, night op, AFAD toggle, pilot car, ped/ADA. No lane-count field — TA-10 is definitionally one lane each way. **Credible detail:** advises a pilot car past 1500 ft per MUTCD §6E; expects 2 flaggers (0 with AFAD).
- **Gated (built, not offered):** lane closure divided (TA-19), work beyond shoulder (TA-1), mobile op 2-lane (TA-35), mobile op multi-lane (TA-26), lane closure near intersection (Cases 18/19). These carry canonical defaults and types but are absent from the enable list — near-intersection is explicitly gated on issue #117.

> Demo note: `ScenarioCard.tsx` is landing-page marketing animation, **not** the real picker. Don't cite it as capability.

### 1.2 The detection pipeline — pin → road facts → suggestions

A map click, marker drag, typed coordinate, or geocoded address all funnel through one detection call (`LocationPickerModal.tsx` → `POST /api/road-bearing`). That endpoint makes **one** Overpass (OpenStreetMap) query across three mirrors and pulls, per nearby road: highway class, name/ref, computed bearing, snap distance, and the raw tags `oneway`, `maxspeed`, `lanes`, `lanes:forward/backward`, `turn:lanes`, plus nearby traffic-signal distance and whether the pin sits in an urban place. From those tags the client derives road type / divided, speed (measured from OSM `maxspeed`, or inferred from road class at lower confidence), and lanes per direction.

Separately, the pin drives a **jurisdiction suggestion**: a debounced call to `POST /api/jurisdiction/suggest`, which does an offline point-in-polygon test against bundled TIGER/Line boundary polygons (`src/rules/boundaries.py`).

**The principle that makes this trustworthy — "suggest, never set."** The detection layer *proposes* values; it never silently writes them into your plan. It's stated verbatim in code: *"a pin can suggest, never set… the only writer of `jurisdiction_key` is the user's explicit Confirm"* (`boundaries.py:7-11`). Concretely:

| Value | Auto-applies? |
|---|---|
| Road classification (type, divided, width, lanes), high-confidence speed | Applied when the operator **Saves** the picker (never mid-session, never silently) |
| Low-confidence (inferred) speed, bearing when ambiguous, multi-candidate road | **Held** — shown but not applied until the operator picks/accepts |
| `jurisdiction_key`, `street_class` | **Confirm-only** — the single writer is the user's Confirm click |

A moved pin invalidates the previously confirmed road and clears everything derived from it, so a stale detection can never quietly feed downstream numbers.

### 1.3 The jurisdiction layer

Jurisdiction rules live as one JSON record per jurisdiction (`data/jurisdictions/`), schema-validated, evaluated by `src/rules/jurisdiction.py`. The module never invents a value — a missing input abstains as `unknown` rather than defaulting. There are **three reachability tiers**, which matters for the demo:

- **Pin auto-suggest can return 6:** Denver, Centennial, Englewood, Lakewood, Littleton, Parker (the ones with boundary polygons).
- **Manual dropdown offers 8:** those six plus CDOT (state-highway baseline) and E-470 (toll authority) — neither has a polygon, so they're dropdown-only.
- **14 data files exist** total; the extra six (Thornton, Westminster, Castle Rock, Greeley, Loveland, El Paso County) are **defined but unreachable** in production — no dropdown entry, no polygon. A pin inside Thornton/Westminster/Castle Rock returns an "unsupported area" warning and baseline rules, **not** a suggestion. **This is issue #155 — do not demo Greeley/Thornton expecting their deltas; they silently fall back to CDOT baseline.**

All six pin-reachable jurisdictions carry real, specific rule deltas beyond baseline MUTCD+CDOT (from their JSON records):

| Jurisdiction | Example real deltas today |
|---|---|
| **Denver** | Arrow board +1 on any lane closure; parking-lane closure → No-Parking R7-1/R7-2 signs; full ped/bike detour regime ≥72 hr |
| **Englewood** | Arrow board +1 (arterial/collector); overnight-excavation flashing barricades; ≥1 lane each direction open |
| **Lakewood** | Arrow board +1 (arterial); double-post advance signs on state hwy w/ median; no overnight open trenches |
| **Littleton** | Flaggers+UTC, **AFADs not accepted**; cones day-only → lighted barricades overnight; no steel plates Sep–May |
| **Centennial** | Arrow panel +1; Type-1 barriers on any excavation; steel plates need authorization |
| **Parker** | Vertical panels for cut/fill ≥2 in within 5 ft of lane; steel plates generally not permitted |

**Count caveat:** only `add_device` deltas mapping to arrow_board / arrow_board_type_c / arrow_panel / drum actually change device *quantities* (`jurisdiction.py:580-585`). Other deltas (no-parking signs, barriers, vertical panels) fire and appear as honest rows but don't inflate priced counts; overnight barricade *swaps* aren't count-applied. This is deliberate honesty, not a bug.

### 1.4 The MHT package outputs

The "package" (Method of Handling Traffic) is four deliverables, all downloadable in the UI (`OutputCards.tsx` + `QuotePanel.tsx`), all generated server-side without stock art:

- **Plan sheet PDF** (`src/rendering/plan_sheet.py`) — landscape 11×17, pure reportlab. Draws road geometry (divided w/ hatched median or undivided w/ centerline), device symbols as geometric primitives, numbered dimension callouts, site-context strips (sidewalk/bike/school), a LEGEND and a NOTES & SIGN SCHEDULE box. Top banner reads `METHOD OF HANDLING TRAFFIC — <project> — <speed> MPH`. A structured title block carries PROJECT / STANDARDS (MUTCD TA + CDOT standard refs) / SHEET / STATUS, stamped **`STATUS: DRAFT — Not for stamping`** in orange. Optional page-2 Mapbox aerial when a token is present.
- **Device list XLSX** (`src/export/device_list.py`) — two sheets. "Device List" columns: Item # · Device Type · Description · CDOT Pay Item # · Unit · Quantity · Notes. "Summary" sheet totals. Honesty detail: signs are billed `EACH` with a note that CDOT Spec 630 actually bills by square foot; jurisdiction deltas with no mapped pay item render `—`, never a fabricated pay item.
- **Pricing quote XLSX** (`src/export/quote_generator.py`) — **five sheets** (Quote Summary, Equipment Detail, Labor Detail, Delivery & Logistics, Terms). Prices per-device daily rates × quantity × days, labor crews (10-hr shift, 1.5× night differential), delivery (`max(distance×rate, min trip charge)`), then overhead 10% and profit 10%. Calibrated to CO Front Range 2026. Terms sheet flags it as a planning estimate.
- **Crew instructions** (`src/narrative/crew_narrative.py`) — Jinja2 Markdown + a phone-readable PDF, from one content path. Device summary, sign schedule in driver-encounter order, setup (downstream→upstream) and takedown (reverse) sequences, Fines-Double safety notes. V1 is pure-template, **no network**; an LLM-refine path (Claude Haiku) exists but is V1.1 plumbing, off by default.

### 1.5 The audit trail — "each cited"

The verification panel (`AuditTrail.tsx`, backed by `src/api/audit.py`) recomputes every intermediate by calling the *same* MUTCD/CDOT functions the layout engine uses, then shows its work across **7 sections**: taper length, buffer space (jurisdiction-aware), channelizing-device spacing + required-vs-actual counts, advance-warning sign table, Colorado Supplement checks, Fines-Double geometry, and the S-630-1 case reference.

**"Each cited" means, concretely:** every section carries both a prose source string and a discrete citation object. Example (55-mph taper): `L = 12 × 55 = 660 ft`, formula `L = W × S`, source *"MUTCD 11th Ed. Sec 6B.08, Table 6B-3,"* CDOT ref *"S-630-1 Case 10,"* citation `§ 6B.08 · MUTCD 2023 EDITION`. The panel's top verdict literally renders **"each cited."**

**The discipline behind it** (why the citations stay honest): a CDOT typical-application harness validates live output against digitized S-630-1 plate fixtures under an explicit match-rulebook; cross-surface tests pin that PDF, XLSX, crew narrative, and audit JSON report *identical* stations/counts/citations; and a snapshot corpus freezes exact citation strings so an edition-number drift breaks a test. Citations are emitted verbatim-or-not-at-all — where the code can't quote a fixture exactly, it stays silent rather than paraphrasing.

### 1.6 The honesty gates — refuses rather than fakes (this is a feature)

Every render/quote/audit path funnels through one server chokepoint (`_placements_for`, `render_api.py:301`), so a refusal is uniform across surfaces: an HTTP 400 whose human-readable message surfaces in the UI as a red `INVALID INPUT` strip + `GENERATION BLOCKED` pill (`StatusBar.tsx`). Three refusals a demo can actually trigger:

- **Single-lane road (#136)** — refuses `lanes == 1` on an undivided road. *"This looks like a single-lane road, which isn't supported yet…"* **Recovery:** flagger — tick *"Road has one lane in each direction"*; shoulder — set the lane count. Confirming clears the detected value and regenerates.
- **One-way road under flagger (#158)** — refuses flagger on a one-way (shoulder on a one-way is fine). *"…a one-way road has no opposing direction to hold, so the plan would direct traffic that isn't there. If the detection is wrong… confirm 'Road carries two-way traffic' and regenerate."* This is the flagship refusal beat.
- **Corridor geometry (taper floor / freeway lane-width / speed-domain)** — e.g. *"Work zone length (X ft) is shorter than the required merging taper of Y ft at S mph. Increase the work zone…, or reduce the speed."* **Recovery:** fix the field and regenerate.

Two more gates exist as guards (gated-scenario-kind; no-devices-generated) but aren't reachable from today's picker. Front-end pre-flight validation also blocks obviously-bad input before any request (work zone ≤ 0 or > 20,000 ft, lane/width overflow of the sheet).

### 1.7 Infrastructure that's invisible but load-bearing

- **Rate limiting (#145):** per-IP, per-route Upstash limiter (render 20/min, audit 30/min, bundle 10/min, geocode 40/min, etc.). **Fails open** by design — if the store is unreachable or env is malformed, it allows rather than 500s (that fail-open regression was itself #145).
- **Modal container backstop:** the Python backend runs on Modal. `min_containers=1` keeps one warm (hides the ~5.5 s cold start); `max_containers=8` is a hard spend ceiling so an anonymous flood can't drain the $30/mo Starter credit into an outage.
- **Clerk production auth — built, flag OFF.** `AUTH_UI_ENABLED` gates on `NEXT_PUBLIC_AUTH_UI === "true"`. Off today, so the homepage *is* the public generator (no sign-in, no Save, no org switcher), and downloads route through the anonymous public endpoints. The full company-forced login/onboarding flow, Clerk→Postgres sync webhook, and middleware all exist behind the flag. `[VERIFY]` the prod env value isn't in-repo, but default + all call sites confirm off.
- **Overpass identification (#147/#148):** both OSM callers send an identifying User-Agent (`conestruct-traffic-control-tool/0.2 …`) across three mirrors, or Overpass blocks them.
- **Geocoding:** server-only Mapbox (`MAPBOX_TOKEN`), also feeds the optional PDF aerial; absent → silent fallback to schematic-only.

## 2. What it can't do today — honest limits

### 2.1 By design, not yet built (roadmap material)

- **New scenario geometry (biggest gap).** One straight road on one axis only. No cross-street-inside-the-work-zone (#117, high priority, spike done), no corner-quadrant work (#128), no curved-road geometry — a curved road is drawn as a straight chord off the pavement (#140). Four "dark" scenario kinds are carried but unvalidated (scoped inside #117).
- **Jurisdiction depth.** Greeley/Thornton have rules but no way to reach them (#155); wave 2 (Castle Rock, Loveland, Thornton) is now unblocked (its on-sheet-summary gate was satisfied by #150) but not built; CO-Supplement citations aren't yet re-verified against the current supplement (#70, #83, #98, #108).
- **MHT-minimum completeness.** CDOT 630.10(a) lists four minimum elements; the bundle nails two. **No written pedestrian/bicycle maintenance statement** (#125, queued) and **no emergency-access plan** (#124, shelved).
- **UX polish.** No shared spacing scale was the just-shipped #165; LocationPicker still needs its own pass (#166); **desktop-only — no responsive/touch/zoom** (#153); several color-only cues (#159, #132, #144).
- **Auth / multi-user.** Built but dormant behind the flag; prod + dev currently share one Neon database and dev Clerk keys can write prod data (#163, infra debt).
- **Perf / reliability.** Sentry import costs ~2.3 s of cold start (#137); the deploy-gap monitor exits green when `/healthz` is unreachable (#134).
- **Input ingestion (big future bet, unscheduled).** Auto-populating form fields from a 500-page civil-drawing bid package (#146, low priority).

### 2.2 Known rough edges live right now — the demo-driver watch list

**Both bugs you'd worry about are still OPEN:**

- **#157 (address/pin mismatch):** the title block prints the *typed address verbatim*, with no cross-check against the pin. Type one address, drag the pin elsewhere without editing the text → the PDF names one city beside another city's aerial, silently. **Rule: don't move the pin away from the typed address unless you also fix the address text.**
- **#159 (pink shoulder):** closed-shoulder pink fill is near-invisible in grayscale. **Harmless on a color screen** (closure is also carried by devices + "RIGHT SHOULDER CLOSED" text). Only bites if you print/photocopy in grayscale.

**Other live oddities a sharp prospect might notice:**
- **#142** — a portable sign can render *off the schematic* in blank space (and lands in the tabulation). Visible on many sheets.
- **#156** — with Denver selected and Denver deltas applied, the XLSX Summary + crew header still print *"Jurisdiction: CDOT."* Awkward if you open the XLSX mid-municipal-demo.
- **#123 / #120** — the detection panel can show a rationale that contradicts its value ("divided: false … couplet → divided"), and OSM turn-lane pockets can inflate the through-lane count near intersections.
- **#141** page-2 aerial has no road names; **#144** arrow-board vs portable-sign legend glyphs look alike; **#86** flagger helper says "2-lane only" but the field accepts an urban arterial; **#135** the quote can sum a cent off from independent rounding.

**Cold-start latency:** ~**5.5 s cold, ~0.5 s warm** (it's Python import, not rendering). Normally hidden — `min_containers=1` keeps one container warm 24/7. It bites right after a redeploy (all cold) or if a second container spins up under load; on a cold hit the strip shows `VERIFYING` for ~5.5 s then the correct verdict (it does not time out, though #122 notes it can occasionally surface as an opaque NetworkError). **Rules: don't redeploy right before the demo; fire one warm-up request first.**

**Demo-environment gotchas:**
- **Auth is OFF** — the homepage silently *is* the generator. No sign-in, no Save, no org switcher; downloads work anonymously.
- **There is no "sandbox/demo" banner.** The only "Sign up to download" copy appears exclusively in saved/workbench mode, which this build doesn't show. Don't promise a banner that isn't there; and note **"Save plans" is genuinely unavailable** in this build.
- **Caps are live** — 8-container ceiling + per-IP limiter. A few simultaneous renders are fine; a whole room clicking Generate at once could hit the ceiling.
- **#163** — dev and prod share one database; don't run a local/dev session against prod during the demo window.
