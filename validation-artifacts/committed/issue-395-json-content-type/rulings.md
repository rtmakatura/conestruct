# #395 rulings

- R1 (R145 self-ruled): the six JSON proxies in `conestruct/site/lib/render-proxy.ts` (fetchQuoteBreakdown, fetchDeviceBreakdown, fetchCorridorGeometry, fetchNearestIntersection, fetchAuditTrail, fetchJurisdictionSuggest) relay the backend's content-type as-is. A 200 that names none is relayed with none and with its body intact (was: labelled `application/json` by `?? "application/json"`). Same handling for all six, through one helper `relayContentType`. Fits Rule 10 because the proxy no longer claims a type the backend didn't name. It matches the download path's existing `if (contentType) headers.set(...)` in renderScenarioToResponse.
- R2 (R145 self-ruled): pass through, not refuse (unlike #390's image path). A JSON body with no header is still the backend's answer, and no site client reads the header on these routes (grep of lib/components/app for `headers.get("content-type")` outside the proxy: only app/api/contact reads a *request* header). A 502 would turn a header the backend left off into an outage on the quote screen. #390 refused because a browser needs a type to show image bytes. JSON callers parse with `res.json()` whatever the header says.
- R3 (R145 self-ruled): `BandAerial.tsx`'s comment says "an image", not "a PNG". `app/api/corridor-map/route.ts:11` ("PNG out") quotes a ruling and stays as written, per the issue.
