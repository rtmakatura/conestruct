- R1 (R145 self-ruled): the guard sits on `httpx.AsyncClient.send` for Overpass URLs only, the lowest layer every real Overpass trip passes through (`_mirror_post` calls `client.post`, which ends in `send`). Tests that stub the chain, `_mirror_post`, or swap `site_detection.httpx.AsyncClient` never reach it, so `test_site_detection.py`, `test_site_scan_ingenerate.py`, `test_overspan_mirror.py` and the rest pass untouched. Other hosts and the sync `httpx.Client` (Starlette's `TestClient`) are left alone: the issue's scope is Overpass.
- R2 (R145 self-ruled): the guard raises `RuntimeError`, not an `httpx.HTTPError`, so `_ask_mirror` (`src/rules/site_detection.py:231`) can't treat it as one mirror's failure. The scan path still catches it upstream and turns it into an `unavailable` scan, so the guard also records each hit and calls `pytest.fail` at teardown: a swallowed hit still fails the test.
- R3 (R145 self-ruled): the two tests that tripped the guard both reach Overpass through the audit's corridor-vs-OSM bearing check (`detect_road_bearing` <- `validate_corridor_against_osm` <- `build_audit_trail`), not the site scan. Each gets the "mirrors down" stub the file already uses (`overpass_down` in test_site_scan_corrections.py; the same lambda inline in test_site_scan_null_geometry.py). Neither test asserts the bearing check, and both passed with the guard raising, so "down" is the same answer they got with the wire refused. No test is marked as a deliberate live test: none needs the wire.
