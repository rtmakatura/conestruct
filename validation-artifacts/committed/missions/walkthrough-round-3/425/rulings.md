## Calls (R145 self-ruled; flagged so Ryan can overturn any of them)

1. **The declined signal's source (R145 self-ruled).** The breakdown's 400, the shell's existing `jurisdictionDeclined` (`GeneratorShell.tsx:1877-1879` on a0c666d), the same source #398 call 3 chose for the windows line, so the two lines switch on one state. #406 proposed the shell's `planDeclined` (`GeneratorShell.tsx:1301`); not taken: it is the audit pair's verdict, a different source from the one that sets `jurisdictionErrored`, and mixing them reopens the window #398 call 3 describes (one line says declined while the other says didn't answer).
2. **One verb, "not checked" (R145 self-ruled).** #425 asks for one verb for the band's "no answer" lines. "not checked" is the issue's proposal and the windows line's verb, already shipped in #398. So the failed-check line moves too: "not checked: the check didn't answer; the option shown stands". This supersedes #406's acceptance line that quoted the old "not evaluated" wording for a 5xx; #425 is the later issue and asks for the one verb. "evaluating" and "evaluated" stay: they name a check that is open or answered, not a missing answer.
3. **The declined line's words (R145 self-ruled).** "not checked: the plan was declined; the option shown stands": the windows line's words, plus the cell's own tail (the option in the select is still the value the plan uses). Step 2 keeps the short form rather than the panels' "unavailable while generation is declined" (`DeviceBreakdown.tsx:128`, `TieredReference.tsx:356`), for #398 call 4's reasons: the band's lines are one-line states in the check's vocabulary, and the panels' form is a sentence that points elsewhere ("See ..."). The panels are not changed.
4. **Tone and marker (R145 self-ruled).** Not red: nothing is wrong with the field (Rule 10, #406). The marker is `◌ not checked`: P9 allows a glyph-less word only for "default" (`DESIGN-PRINCIPLES.md:61`), and `◌` is the table's "unevaluated / not set / pending — never a verdict" (`DESIGN-SPACING.md` glyph table), which is what a declined plan's jurisdiction is. The line goes behind the marker, one click away (R98), not on show: P3 keeps on show only a line that needs the operator now, and the next step is the PLAN DECLINED banner's, not this field's. Open edge, recorded not changed: #398's windows line shows the same state with no glyph (`ScheduleField.tsx:213`), a footer line whose sibling "set dates to check" also has none.
5. **A pin guess keeps its marker (R145 self-ruled).** #406's acceptance: "a pin guess keeps `⚠ from the pin`". The guess line stays the row's line (R108), amber, and the declined sentence goes to the row's details, as the evaluated sentence does for a guess (`WhatBand.tsx:705-712`). The failed check keeps winning over the guess (P3, unchanged).
6. **The cell's height on a declined plan (R145 self-ruled, recorded).** With the line behind a marker the cell is shorter: 1440 407 x 102.5 -> 407 x 65, 390 328 x 152.5 -> 328 x 115 (both -37.5 px). #276's "no height change" reserve (`app/globals.css:5320-5323`) holds for the on-show line's states; a marker row is the R98 form every guessed row already uses, so this is the same height as any other marker row, not a reflow of the line. The content below moves up 37.5 px on a declined plan.
