## Calls

1. **W4's cause, confirmed (R145 self-ruled).** The issue named a likely cause, "A post-audit write to the scenario (for example the `/api/distance` result) would hold either one open. Unconfirmed." That is not it: `/api/distance` writes `settings`, not the scenario (`QuotePanel.tsx:237` `setSettings({`, with `delivery_distance_miles: miles,` at `:239`). The confirmed cause is `fetchDeferred` comparing the live scenario against the debounced wire scenario. `git log -L925,925` dates that line to f20057f (2026-08-02, #182), before `withSiteScan` went on the wire in 6d3baee (2026-09-03, #224 phase 2), so the comparison was right when written and went stale when the wire scenario split from the live one. The mounted test reproduces it (the cue reads "◌ previous answer, refreshing…" with no audit open and no further audit sent), and so does the local dev server on the base: 10 s after every `/api/` request answered, the cue was still up at 1440 and 390 (`shots/text-before.json`, taken with the committed `script/shoot.mjs` on a `git archive` of 63f2d42: `shoulderOpenRequests: []` and `cue: "◌ previous answer, refreshing…"` at both widths). With the one-line fix the same run leaves the slot empty (`shots/text-after.json`). It needs a plan with a jurisdiction (the held block is what `jurisdictionRevalidating` reads), which is why #187's older test (no jurisdiction, `GeneratorShell.disclosures.test.tsx:251-272`) never saw it.
   - Same root, possible but not separately observed: `jurisdictionLoading` (`:939-942`) reads the same `breakdownInFlight`, so a generated plan whose breakdown had no held block could have read "evaluating" too. The one-line fix covers both.
   - The `auditSettled` stamp (`:446-448`) compares against `wireScenario` already and was not the cause.
2. **W5's words (R145 self-ruled).** "not checked: the plan was declined" is the issue's own proposal. A failed check that is not a decline had the same never-ending "loading"; it reads "not checked: the check didn't answer", the jurisdiction cell's words for the same state (`bands/WhatBand.tsx:399`, "not evaluated: the check didn't answer; the option shown stands"). Folded under R154: same function, no ruling or source needed, inside the prediction, a few lines. Both lines take no glyph and the `--none` tone (Rule 13: no verdict, chromaless gray); ◌ stays the glyph of an open wait.
3. **Which signal says "declined" (R145 self-ruled).** The breakdown's own state (`deviceBreakdown.state === "error" && httpStatus === 400`), the same source as `jurisdictionErrored` (`GeneratorShell.tsx:1874`). The `refusal` prop is "stamped for the scenario on screen" (`GeneratorSidebar.tsx:51-52`), so after an edit it can go null while the breakdown still holds its error. Mixing the two sources could then show "the check didn't answer" for a decline in that window (possible, not observed). Sharing a source keeps the windows line and the Jurisdiction cell switching on the same state; it does not make them say the same thing. On a declined plan the cell reads "not evaluated: the check didn't answer; the option shown stands" (`bands/WhatBand.tsx:398-399`, through `jurisdictionCellState`'s `return opts.errored ? "not-evaluated" : "evaluating";` at `:98`), while the windows line reads "not checked: the plan was declined". The cell's "didn't answer" is wrong under Rule 10 (the check did answer, with a decline), and the two lines use different verbs. `WhatBand.tsx` is not in this branch's code files, so this fails the R154 fold test; filed as #425 (https://github.com/rtmakatura/conestruct/issues/425).
4. **The declined line keeps "not checked: the plan was declined" (R145 self-ruled, repair cycle 1).** Considered instead: the panels' "unavailable while generation is declined" (`DeviceBreakdown.tsx:128`, "Device schedule unavailable while generation is declined. See"; `TieredReference.tsx:356`, "Audit trail unavailable while generation is declined. See the"). Kept, for three reasons. The line's sibling states are all in the check's own vocabulary ("select a jurisdiction to check", "checking your dates", "set dates to check", `ScheduleField.tsx:200-215` at 63f2d42). The issue proposed these words. And "declined" is still the reason given, matching the "PLAN DECLINED" banner. The panels' form is a full sentence that points elsewhere ("See ..."), which a one-line footer state doesn't have room for. Settling one verb across the band and the panels is part of #425. No copy changed in this cycle, so the W5 after shots stand.
