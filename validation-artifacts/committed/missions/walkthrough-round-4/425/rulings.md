## Calls (R145 self-ruled)

1. **The marker and the colour (R145 self-ruled).** `◌ check failed`, tone `pending` (`--none`, chromaless gray). Rule 13: "no-verdict renders chromaless gray", and a failed check gave no verdict on the jurisdiction. `◌` is the table's "unevaluated ... never a verdict" (`DESIGN-SPACING.md:143`). Not `⚠` (amber): `⚠` is "changed / needs attention / conflicts; a guess to check", and it would count the failure among the band's "guesses marked ⚠", which it isn't. Not `×` ("dismissed — a recorded decision"). The word "check failed" is the second channel, so the state is not carried by hue (Rule 13, P9).
2. **Behind the marker, not on show (R145 self-ruled).** With no red the row is no longer an error, so it takes the marker form every non-error row has (R98), as the declined row does (round-3 call 4): the line is one click away. P3 keeps on show only a line that needs the operator now; the field has nothing for the operator to do on a failed check (the option shown stands, and the check re-runs when the plan changes).
3. **A pin guess keeps its marker (R145 self-ruled).** The failed check no longer wins over the guess: no red means no error line to keep on show (round-3 #425 call 5's reasoning for the decline, now for both). The guess line stays the row's line (R108), amber, and the failed line goes to the details. This reverses the round-3 test "wins over a pin guess (P3, unchanged)", whose basis was the red error line Ryan ruled out.
4. **The words (R145 self-ruled).** The cell: "check failed: the check didn't answer; the option shown stands": Ryan's verb, then the reason and the tail the line already had, so only the verb moves. The windows line: "check failed: the check didn't answer", the same. The boundary lookup: "The boundary check failed, so nothing was filled in from the pin." (it is a check that ran and failed, in the cell's details; its own loading line says "Checking boundary data…", so "boundary check" names the same thing). Its `◌` glyph stays.
5. **The state's name (R145 self-ruled).** `"not-evaluated"` becomes `"check-failed"`, so `data-jurisdiction-state` says which of Ryan's two cases holds. The prop `jurisdictionErrored` keeps its name: it is the breakdown's error, decline included.
6. **Not moved (R145 self-ruled, recorded).** Lines outside the WHAT band and step 2 are out of the ruling's scope: `AuditTrail.tsx:1334` ("... was not checked. Re-generate to retry.") and the results panels' "unavailable while generation is declined" (declined, so "not checked" is right there anyway). `JurisdictionSection.tsx:394` ("Schedule not checked yet") and `:509` ("windows shown · not checked") are for checks that haven't run, so "not checked" is right.
