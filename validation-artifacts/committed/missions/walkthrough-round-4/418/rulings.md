## Calls (R145 self-ruled)

1. **R145 self-ruled: mark the carried count; don't reset it.** The issue offers either. Resetting to the kind's default on a re-pick would change a plan value and the payload (and refit the lane width written in the same patch, auto-apply.ts:614-624), and would throw away a count that is often right (a re-pick onto the next untagged segment of the same road). The issue says the gap is "copy and marker only". So the value stays and the row says where it came from.
2. **R145 self-ruled: the marker is "⚠ from an earlier road", amber, counted in the header's N.** #411's vocabulary gives ⚠ to "a guess to check (from the road ...)" (DESIGN-SPACING.md:141), and Ryan's 2026-10-27 ruling (on #397, https://github.com/rtmakatura/conestruct/issues/397#issuecomment-6435842275, filed as #420) counts the near-intersection lane doubt as a guess because the count "isn't from the road" (Rule 10). That ruling covers the near-intersection doubt only; the shoulder marker here stands on #411's vocabulary (R145), with the ruling's reason as support. A kept count is the tool's carry-over, not this road's and not the operator's, so it is a guess to check. Not ◌: ◌ means "not set", and the plan has a value that Generate will use. The word follows "⚠ from the road" / "⚠ from the pin" (R108). The line puts the word last, `not confirmed · set the real count · from an earlier road`, as the speed guess does (`guessed, not confirmed · OSM highway=… · from the road`), so `markerOf`'s amber path names it with no marker edit (provenance-marker.ts, the `opts.amber` branch).
3. **R145 self-ruled: how a carried count is told apart (a frontend reading, not a value, Rule 3 n/a).** There's no record of where an untouched shoulder count came from. With no map count behind the row and no operator record, the count came from the kind's default (2, index.ts:117), the divided reset (2 divided / 1 undivided; `setRoadType`'s reset now reads `shoulderRoadClassLanes` in what-writes.ts, while `components/bands/PlanDetails.tsx:379` still writes `lanes: v ? 2 : 1` by hand, untouched) or an earlier road's map count (auto-apply.ts:617-619). Any count that isn't one of those defaults must be an earlier road's. **Recorded residual:** a carried count equal to a default (an earlier road's 2, or 1 on an undivided plan) still reads "default". The value is the default's value, so the word is true of the number, but the history isn't shown. Telling those apart would need a new source record in `meta`, written by `applyClassification`, cleared by the divided reset and `setLanes`, and carried in saved plans. That is a bigger change than this item. Filed as #434 (priority-low), with call 7's imprecise-source cases: https://github.com/rtmakatura/conestruct/issues/434
4. **R145 self-ruled: the turn-lane reason only for a map count above the plan's (b).** As the issue proposes. A map count equal to or below the plan's keeps the doubt line and its ⚠, which counts in the header (#420, unchanged), and drops the reason: `⚠ not confirmed · the map reads N per side`. Ryan's #397 ruling ("the ⚠ moves to the doubt line") is untouched.
5. **R145 self-ruled: one clause (c).** The default line on a detected road with no count reads `default · the map has no count here; set the real count`: one fact, then the action (docs/style.md unslop rules). "not from this road" is dropped from it, because "default" and "the map has no count here" already say so. The undetected line (`default · set the real count`) and the near-intersection lines are unchanged.
6. **Rule 5 actual vs predicted.** WhatBand.tsx ~+25/-8 -> +36/-15 (over, because the `clauseFor` call is re-indented one level under the new branch, about 11 lines that change only whitespace and its comment); what-writes.ts ~+6/-1 -> +8/-1; untouched-provenance.test.tsx ~+70/-3 -> +76/-2. Rule 5 miss, recorded: the prediction's "byte-identical ... the undetected `default · set the real count`" holds only for a 2, or a 1 on an undivided plan; call 7 states the rest.
7. **R145 self-ruled: a count with no road read is marked too.** `lanesCarried` checks only that there's no map count behind the row, not that a road was read, so an unrecorded shoulder count other than 2, or 1 on an undivided plan, reads "⚠ from an earlier road" when no road is read at all (so a divided plan holding 1 is marked too: a legacy migration with `divided: true, lanes: 1`, or a re-pick from an undivided road at 1 per side). That covers four cases: the pin moved off the confirmed road; a pin saved with no road picked; a legacy flat-plan migration (`lib/scenarios/index.ts:671`, `lanes: p.lanes` with no record); a count typed before #397's record. Kept: in all four the old "default" was false (the count is neither the kind's default nor the reset's for the plan's divided-ness), and a ⚠ to check beats a false "default" (Rule 10). For the first two the source word fits. For the last two it is imprecise (the count came from a migration or the operator, not an earlier road). Closing that needs the same per-count source record as call 3's residual, so it is in #434.
