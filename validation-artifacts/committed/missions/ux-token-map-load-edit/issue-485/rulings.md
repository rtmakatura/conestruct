## R145 self-ruled (CC, 2026-11-10)

- **E1, which answers an edit invalidates (the existing code, not a new guess).** The edit changes three things; each one's effect on the answers is already settled:
  - *The road (Change) and the work start (Move)* both open the picker, and its Save already clears the side when the pin moved or the way changed (#290 ruling 10, `withPin` / `withoutSide`, `GeneratorSidebar.tsx:337-341`). The cross street is whatever the picker saves (`intersection: r.intersection ?? null`, `GeneratorSidebar.tsx:357`); the picker is handed the current one, and a pin move or road change keeps it (`LocationPickerModal.tsx:1483-1487`), so it goes only when the person presses Clear in the picker (`clearCrossPin`, `LocationPickerModal.tsx:840-846`). The kind is never touched by a picker save (it is chosen, never inferred: #289).
  - *The length* changes no answer. The side options read the centreline, the pin, `meta.roadDirection` and `left_side_built` (`src/api/render_api.py:1598-1657`), never `workLen`; the kind and the cross street are not read from it. A crossing the new length puts inside the work zone is the backend's own refusal (`work_start_cross_station`, `src/api/schemas.py:1489-1492`), shown as it is today; nothing is cleared for it.
  - So "an answer the edit invalidated" = the side, when it was set when the panel opened and is unset when the person presses Done. Nothing new decides it; the panel only compares before and after. *Amended in repair cycle 1 (reviewer, Rule 10):* the first build also re-asked the cross street the same way, but its only way out inside the panel is the person's own Clear, which the edit didn't invalidate; the person removed the answer. It is now simply unanswered: the card opens on it (E4), with no line. Every other answer stays (it was never touched). No device count changes: no producer of a count is touched.
- **E2, the line.** #440 ruling 2's line names its cause ("…with the new kind of work."), so the edit's line names this one: **"Your edit changed the road or the work start, so this is asked again."** One line, for the re-asked side only (repair cycle 1: the cross street the person cleared gets none, since this reason would be false for it), a plain note like X21 (no ⚠), shown under the question while it is unanswered, gone once it is answered. It never shows for a length-only edit (E1: nothing is cleared). If the side was cleared by a kind change instead (X20), X21's line shows and this one doesn't.
- **E3, Cancel (P15).** Opening the panel takes a copy of the scenario and of the sidebar's picker memory (the applied-detection and applied-cross-street guards, the lane-count hold, the handoff notes, the picker picture). Cancel writes the copy back (the same object, so the wire is byte-identical) and restores the memory, then closes the panel; a picker Save made inside the panel is undone with it. Cancel is a write (`data-write`), under the write lock like every write.
- **E4, Done.** Done closes the panel and the questions come back. The card opens on the first unanswered question (QuestionSteps' own rule, `firstOpen`), so a re-asked one is on screen. A typed length is committed on the field's blur as today (#252), which runs before the click. While the length is unset or refused (the field's own error) Done keeps the panel open and shows the field's error line, so the panel never closes over an owed control (P5). Cancel is not guarded the same way: when the panel opened by itself because the length is owed, Cancel puts back the pre-edit scenario (the length still owed) and closes the panel, as the old Edit toggle let the fold close (#439 W9). Kept, not changed here (repair cycle 1, recorded at the reviewer's request).
- **E5, what opens the panel.** Edit (the summary row's link) while the CONFIRM card is there. Change, Move and the length field live in the panel, so they are inside the edit already. As today (#439 W9) the panel also opens by itself while the length is unset or refused. "Edit on map" on the aerial's corner is not in the ruling's list and stays the picker's direct door, unchanged; with no panel open there is no "back on the questions", so no line. Recorded as a known limit, not built here; filed as #488.
- **E6, the panel's rows.** The ruling's three, each with its own action: **Road** (the ledger's `spot` value, `Change` opens the picker), **Work starts** (the ledger's `start` value, `Move` opens the picker), and the **Work zone length (ft)** field (today's `FieldCell`, its marker, details and error line unchanged; the field is the row's action). Labels: "Road" is the canvas's; "Work starts" and "Work zone length (ft)" are today's. The values come from `deriveMoveLedger` (no new derivation, Rule 3). The ledger's `extent` row ("1,000 ft · default", CHANGE opening the picker) and the address field are not in the panel: the canvas has neither, the length field says the same thing (its marker reads default / ✓ yours), and the picker has its own address search (`LocationPickerModal.tsx:1566`), which Change and Move open. Stated as a narrowing (Rule 5). The old fold stays as it is where the CONFIRM card isn't shown (a stale road).
- **E7, the collapsed row.** WhereQuestions renders it in place of the card while the panel is open: "◌" (`symClass("◌")`, aria-hidden) and **"Questions wait while you edit · N of M answered"**, N and M counted from the same question list the card would show (answered = an answer set). A plain `div`, no button, no tabindex, no handler (ruling 3: not a control). While it shows, the aerial takes no tap and shows no tap bar (no question is on screen to answer), and no load-ahead runs.
- **E8, the layout.** Two columns: the stack carries `data-edit`; the right column is exactly `--wq-band-h` tall (`height`, not `min-height`), the panel takes the room the row leaves (`flex: 1 1 auto; min-height: 0`), the row is 48 px. No `overflow` on the panel: the length's details popover floats and a scroll box would clip it; the panel's content (584 px box, content well under it, measured in the walk) fits the 648 px column at 1440 and 1198. The summary row is hidden (the same node stays mounted). The aerial column keeps its 648 px and its frame. One column (a phone): `data-card="open"` stays on while the panel is open, so the 150 px strip stays pinned under the nav (#456 M4) and the panel and the row flow under it. Sizes and colours are the existing tokens: the panel's border `--act`, the row's `--rule` on `--da-ground`, type `tr-section` (10), `tr-note` (12.5), `tr-help` (13.5), buttons 44 px. No new size, no new hex.
  *Added in repair cycle 1, R145 self-ruled:* ruling 3's "The band's height never changes (#469)" is read as #469 built it. In two columns the band is one height, `--wq-band-h`. In one column (#456's narrow layout) #469 sets no height, so the band follows its content there, as it does in every CONFIRM state today. On a phone the panel and the waiting row take their turn under the pinned strip, and the band can be taller or shorter than the card it replaces. The walk measured this (evidence.md § 390).
- **E9, headings and focus.** The panel's head is an `h2` "EDIT" (the CONFIRM `h2` is gone while it shows, so axe heading-order holds) with "Where the work is" beside it. Opening the panel by Edit moves focus to the panel's heading (`tabIndex=-1`); Cancel and Done return it to the summary row's Edit link (the person's way back in).
- **E10, the permanent check (ruling 4, bullet 2).** Extended in the #469 check's two layers: `WhereBand.one-height.test.tsx` walks Edit, Cancel, Edit, a length change and Done, asserting in each state that the stack keeps the two-column attributes, the aerial frame and the summary row are the same nodes, and the CONFIRM card is the waiting row while the panel is open (that the row is not a control is pinned in `WhereBand.edit-turns.test.tsx`); its CSS layer pins the panel-mode rules (the right column's exact height, the panel's flex, the row's 48 px). The measured 0 px is in this folder's walk (`script/walk.mjs`), at 1440x900 and 1198x930, with the 390 strip pinned in every question and panel state.
