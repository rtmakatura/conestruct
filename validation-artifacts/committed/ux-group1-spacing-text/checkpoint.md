### Calls inside the picker (R145 self-ruled; say if you want any of them different)

- **C1, road class in plain words.** No mapping exists; `humanizeHighwayClass` (`lib/road-detection/labels.ts:24`) gives bare words like "Primary". I'd add `plainRoadClass()` beside it: motorway → "Freeway", motorway_link → "Freeway ramp", trunk → "Highway", primary → "Primary road", secondary → "Secondary road", tertiary → "Minor road", *_link → "<x> ramp", residential → "Residential street", unclassified → "Local road", living_street → "Residential street", service → "Service road". Anything else stays the raw tag (Rule 10: no invented word). `humanizeHighwayClass` and `candidateLabel` stay unchanged, because band-facts.ts:113 and :208 read them.
- **C2, sentence case.** The name renders as `"{primary}, {direction lowercased}"` with no CSS uppercase, e.g. "East Colfax Avenue, westbound". The OSM name keeps its own case.
- **C3, where the "i details" toggle sits.** A row is a `<button>`, so a toggle can't nest inside it (invalid HTML, and it breaks the accessible name). There is **one "i details" toggle in the picker's header row**, opening a list with, for each road: name, way ID, bearing in degrees and "from OSM". The summary row gets its own toggle, beside Change, holding today's `CandidateCaption` text verbatim. Both reuse FieldCell's toggle and popover markup and classes (`a-lk a-info-toggle` / `a-info a-pop`, `FieldCell.tsx:152-187`). I'd pull them into a small `InfoToggle` component that FieldCell then uses itself, rendering the same DOM.
- **C4, the radio marker and selection state.** The rows become `role="radio"` inside a `role="radiogroup"` labelled by the header, with `aria-checked`, so the picked state is in words for assistive tech. On screen, the filled-vs-outline square plus the `--act` border are a shape channel, not hue alone (Rule 13). The marker is a CSS box, not a glyph, so it adds nothing to the P9 vocabulary. Tests that find rows by `getByRole("button", {name: /eastbound/})` move to `"radio"`.
- **C5, header word.** Two or more roads: "⚠ PICK THE ROAD · N FOUND". Once picked, the summary row replaces the list (ruling 5), and the "Road picked · N detected" header goes.
- **C6, one road found.** Today it reads "✓ Road detected · 1 match", with the row pre-selected and no Change button. I'd render it as the ruling-5 summary row too (✓, ROAD, name, i details), with **no Change button**, since there's no other road to change to. Re-detect (moving the pin) stays as it is.
